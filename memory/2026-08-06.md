## Sesión tarde: Diagnóstico del flujo de autenticación (Login no deja entrar en SM-A546E)

### Síntoma
Login con usuario/contraseña en dispositivo físico no permite acceder; no se veía mensaje claro.

### Diagnóstico
1. **Endpoint**: Supabase es público HTTPS (`https://olskjkbyzpowxlhjhovu.supabase.co`), NO localhost. `usesCleartextTraffic="false"` en AndroidManifest es correcto. El único HTTP local es `conversionServiceUrl` (`http://localhost:8080`) que NO participa en login y en físico fallaría por cleartext (solo afecta conversión Office).
2. **Causa raíz (lockout silencioso)**: `router_provider.dart` decide autenticación con el `StreamProvider authProvider`, NO con el `authStateProvider` que usa el formulario. El stream hacía `users.select().single()` SIN try/catch: si fallaba (p. ej. `PGRST116` por usuario sin fila en `public.users`, o error RLS/red), la excepción mataba el stream `async*` → Riverpod quedaba en `AsyncError` para siempre → tras login "exitoso" el router rebotaba a `/auth` sin mensaje.
3. `signIn` capturaba errores pero no los imprimía; la UI mostraba mensaje genérico.

### Cambios
- `lib/providers/auth_provider.dart`:
  - `authProvider` blindado: todo error de lectura de `public.users` se captura y loguea (`debugPrint`), el stream NUNCA muere. En `PGRST116` crea el registro en `public.users` (reutilizando la misma lógica idempotente que signIn).
  - Helper top-level `_fetchUserRow` y `_createPublicUserRecord` (idempotente, ignora `23505`); `AuthNotifier._ensureUserRecord` delega en `_createPublicUserRecord`.
  - `signIn`: `debugPrint` con email, userId de sesión, `PostgrestException` (code/message) y error completo (tipo+stack).
  - Import `package:flutter/foundation.dart` para `debugPrint`.
- `lib/screens/auth/auth_screen.dart`:
  - `_login()`: captura `l10n` antes de awaits (evita lint), loguea error, muestra mensaje mapeado.
  - Helper `_loginErrorMessage()`: `AuthException` "invalid login credentials/email" → `loginInvalidCredentials`; resto → `errorSignInFailed` (localizado en 5 idiomas).
  - Import `package:supabase_flutter/supabase_flutter.dart` para tipos.

## Sesión noche: Diagnóstico p2p del flujo Office → PDF (preview no visible en receptor)

### Síntoma
Upload de .docx (182 KB y 32 MB) completo OK, pero el receptor ve "Formato protegido / conviértelo a PDF antes de subirlo" al abrir el link.

### Diagnóstico
- El mensaje del visor se muestra cuando `conversion_status == 'failed'` (viewer_screen.dart:593). La conversión falló en el EMISOR durante el upload (nunca se bloqueó la subida por diseño).
- **Causa raíz 1 (red)**: `conversionServiceUrl` default era `http://localhost:8080`. En dispositivo Android FÍSICO, `localhost` = el teléfono, NO el PC del gateway → connection refused → `conversion_status='failed'`.
- **Causa raíz 2 (cleartext)**: `usesCleartextTraffic="false"` en AndroidManifest bloquea HTTP plano (Android 9+ / SM-A546E es Android 14) → incluso con la IP LAN correcta la petición sería bloqueada.
- El flujo del visor estaba BIEN: `useViewerObject: true` + `hasPdfPreview` (`conversionStatus=='ready' && viewerObjectKey!=null`). Nunca se llegaba a ejecutar porque no existía el preview.

### Cambios
- `lib/utils/constants.dart`: default `conversionServiceUrl` → `http://192.168.68.112:8080` (IP LAN del gateway). Comentario actualizado: físico usa IP LAN; emulador 10.0.2.2; prod `--dart-define=CONVERSION_SERVICE_URL=https://convert.kriptonshare.com`.
- `android/app/src/main/AndroidManifest.xml`: `usesCleartextTraffic="true"` + comentario (solo dev; volver a false en prod HTTPS).
- `lib/services/conversion_service.dart`: logs `[CONVERSION] POST <url>` (tamaño/max), `HTTP <status>: <n> bytes PDF`, y en DioException: endpoint, tipo, status, code, serverError, message.
- `lib/providers/file_provider.dart` (`uploadAndCreateLink`): log de `viewer_object_key=<uuid>` + bytes PDF/cifrado y `conversion_status=ready viewer_file_size_bytes=... viewer_object_key=...`.
- `lib/features/upload/data/repositories/upload_repository_impl.dart`: misma paridad de logs.
- `lib/screens/viewer/viewer_screen.dart` (`_decryptAndView`): log `conversionStatus / viewerObjectKey / hasPdfPreview / usePreview`.

## Turno posterior: diagnóstico gateway Docker (la petición NO llega a :8080) + mejoras de logs/SnackBar

### Hallazgo del usuario
`docker compose logs -f` en `infra/conversion/` NO muestra la petición de conversión cuando sube un .docx desde el celular físico. Conclusión: el fallo es del lado cliente (el request nunca llega al gateway).

### Causas probables (para comunicar al usuario)
1. **Build desactualizado en el teléfono**: si el APK instalado se compiló con `--dart-define=CONVERSION_SERVICE_URL=http://localhost:8080` o antes del cambio de default, el teléfono sigue llamando a `localhost` (él mismo) → `SocketException: Connection refused` inmediato, sin llegar al gateway. → REBUILD + reinstall.
2. `usesCleartextTraffic="true"` es solo de dev; un build viejo lo tendría en `false` y bloquearía el HTTP.
3. Teléfono y PC en distintas redes Wi-Fi / firewall de Windows bloqueando el puerto 8080 inbound.

### Cambios de código aplicados
- `lib/services/conversion_service.dart`:
  - Log en constructor: `[CONVERSION] Gateway URL: ...` (verifica el default en runtime).
  - En `on DioException`: ahora imprime `rootCause=e.error` (SocketException/ConnectionError/Timeout subyacente) y el mensaje del `ConversionException` incluye `[${e.type}] ${rootCause}`.
  - Añadido `catch (e, st)` genérico → `ConversionException('network', ...)` para que `file_provider` siempre reciba causa exacta.
- `lib/providers/file_provider.dart`: firma del callback `onConversionStatus` pasó a `void Function(String status, [String? detail])`. En `'failed'` se pasa `'$code: $message'`.
- `lib/features/upload/presentation/screens/upload_screen.dart`: en el callback `'failed'` se hace `debugPrint` del detalle y se muestra **SnackBar** con `l10n.conversionPreviewFailed` (mensaje: "No se pudo generar la vista previa PDF (Error de conexión al servidor de conversión)").
