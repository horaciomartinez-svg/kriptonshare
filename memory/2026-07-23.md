# KRIPTONSHARE — 2026-07-23

## Problema reportado
El receptor no ve archivos recibidos en el Dashboard, aunque el link aún no haya caducado. La sección "Archivos recibidos" aparece vacía.

## Causas identificadas
1. La función RPC `get_received_files()` solo existía en `supabase/test_e2e_setup.sql`, no en `supabase/schema.sql` ni en `supabase/schema_migration_fix.sql`. Si la base de datos de producción no la tenía, la RPC fallaba o devolvía vacío.
2. La función comparaba `sl.recipient_email = auth.email()` de forma case-sensitive. Si el email se guardó con mayúsculas/minúsculas diferentes, no coincidía.
3. Las políticas RLS de `share_links` y `files` solo permitían al creador (`owner_id = auth.uid()` / `created_by = auth.uid()`), impidiendo una consulta directa de fallback.

## Cambios realizados
- `supabase/test_e2e_setup.sql`:
  - Comparación de emails case-insensitive en `get_received_files()`: `LOWER(sl.recipient_email) = LOWER(auth.email())`.
  - Agregadas políticas `link_recipient_access` y `file_recipient_access` para receptores.
- `supabase/schema.sql`:
  - Agregada función `get_received_files()` con comparación case-insensitive.
  - Agregadas políticas `link_recipient_access` y `file_recipient_access`.
- `supabase/schema_migration_fix.sql`:
  - Agregadas las mismas políticas y función (numeración 6 y 7), para aplicar en bases de datos existentes.
- `lib/providers/file_provider.dart`:
  - `getReceivedFiles()` ahora loguea el email del usuario y la respuesta de la RPC.
  - Si la RPC falla o devuelve vacío, intenta un fallback directo a `share_links` con join a `files`.
  - El fallback aplana la respuesta anidada para construir `KriptonFile` correctamente.

## Pendiente / Acción requerida del usuario
1. Ejecutar `supabase/schema_migration_fix.sql` en el SQL Editor de Supabase (o aplicar la migración correspondiente) para crear `get_received_files()` y las políticas de receptor en la base de datos de producción.
2. Volver a compilar y probar en el dispositivo Android.
3. Verificar en los logs de VS Code que aparezca `[getReceivedFiles] RPC returned N files` o `[getReceivedFiles] Fallback response: N rows`.

## Soporte de imágenes y documentos Office

### Pregunta del usuario
¿La app ya está programada para visualizar imágenes y documentos de Microsoft Office de forma segura (sin descargar ni capturas)?

### Respuesta técnica
- **Imágenes**: sí, se visualizan con `Image.memory` + `InteractiveViewer`.
- **Microsoft Office (Word, Excel, PowerPoint)**: no. El visor solo muestra una pantalla de "Formato protegido"; no renderiza el contenido.
- **PDF**: sí, con `pdfrx` nativo dentro de la app.

### Problemas de seguridad encontrados y corregidos
1. El visor de imágenes podía mostrar el menú contextual nativo de guardar/compartir al mantener presionada la imagen.
   - Solución: envolver `Image.memory` en un `GestureDetector` con `onLongPressStart` para interceptar el menú.
2. El `AppBar` del visor PDF tenía un botón "Abrir con otra aplicación".
3. El fallback de PDF mostraba un botón "Abrir con otra aplicación".
   - Solución: eliminar ambos botones; el fallback ahora solo muestra un mensaje y un botón "Volver al inicio".
4. Se eliminó código muerto asociado: `_openWithExternalApp`, `_prepareTempPdfFile`, `_deleteTempPdfFile`, `_tempPdfFile`, e imports de `dart:io`, `open_filex`, `path` y `path_provider` desde `viewer_screen.dart`.
5. Se actualizó el mensaje para formatos no soportados (Office) explicando que deben convertirse a PDF antes de subirse.
